# 安全模型与使用规范

## 本质

本 skill 是一个**本机会话凭据读取器**：从用户自己的浏览器读取用户自己的登录态。
它不是漏洞利用工具，但能力边界等同于“能读你所有登录态的程序”，因此必须按
敏感凭据工具的标准使用与分发。

## 威胁模型

- **同机其他进程**：调试端口只监听 `127.0.0.1`，但同机任何进程都能通过 CDP
  读取全部 Cookie。专用实例的调试端口不应长期挂起。
- **恶意 prompt / 子 Agent**：任何能调用本 skill 的上下文都能静默读取登录态。
  所以 skill 的指令里必须强制：目标域名来自用户明确请求、不枚举、不导出全量。
- **日志与回显**：Cookie / Token 明文进入终端、对话或日志即等于泄露。
- **供应链**：本 skill 无第三方依赖（纯标准库 + 官方 WASM），交付物应保持零依赖，
  不要引入来历不明的 pip 包。

## 必须遵守

1. **用户知情**：首次使用前说明“将读取 X 域名的登录态”；浏览器重启发生在
   `--setup` / `--resync`，需要用户可感知。
2. **最小范围**：只读取用户指定的域名；绝不调用“导出全部 Cookie”的逻辑。
3. **不落地**：凭据不写入文件、不进日志、不打印完整值；输出用 `--json` 供程序
   消费，展示时脱敏（如只显示末 4 位）。
4. **及时关闭**：任务结束 `--close-browser` 关闭专用实例，或至少提醒用户。
5. **不做对抗**：不绕过验证码、不模拟人机校验、不伪装成真人操作、不规避风控。

## 合规提示

- 自动复用浏览器会话可能违反目标站点 ToS，使用前确认用途边界；
- 在受控环境（本机自动化、测试）之外分发前，需要明确的法律与合规评估；
- macOS 首次授权（Keychain 之外的调试连接）与 auto-connect 的人工确认，
  本身就是操作系统的安全边界，**不要尝试绕过**。

## 分发形态建议

如果作为 Skill / Agent 工具分发给他人：

- SKILL.md 里保留本安全章节（用户可感知边界）；
- 默认不自动启动调试实例，由显式命令触发；
- 提供 `--close-browser` 作为默认收尾动作。
